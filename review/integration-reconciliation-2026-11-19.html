Suggested path before trusting a team or strategy

  1. Resolve data rights first. Obtain written permission or a licensed feed; document retention and derived-publication rights. Keep all capture jobs fail-closed until verified.
  2. Use one immutable input manifest. Record source, UTC retrieval time, hash, included game IDs, parser/model version, and conflicts. Corrections are new captures, never silent overwrites.
  3. Build availability as a time series. Join permitted dated injury/practice reports and official roster/transaction events to pre-game expected starters, game-day inactives, actual Game Book starters, and playing time. Keep shared/empty slots and missing values explicit.
  4. Do not infer 1st–4th string from one week. Build playing-time features from chronological windows with position/unit groups and time cutoffs; validate across 32 clubs and multiple seasons before any team-level claim.
  5. Use paired personnel ablations. Compare identical models with/without verified availability features on chronological holdouts; publish the delta, sample size and game-cluster uncertainty. Do not use fixed injury penalties or an injury level as a surprise signal.
  6. Keep the strategy competition evidence-led. Pre-register, evaluate singles first, publish probabilities with inputs, use proper-score skill and uncertainty before prospective CLV/ROI escrow. Parlays/props require validated joint probabilities and operator-specific push/void rules.
  7. Keep owner decisions open rather than guessed. Data-use permission, price-source budget/rights, and the meaning of a leaderboard reward need an explicit recorded decision.
