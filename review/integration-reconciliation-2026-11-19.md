# NFL source and site reconciliation — 2026-11-19

**Status:** Flagged for Review. This is an integration audit, not a new NFL data capture or a betting recommendation.

**Scope:** Reconcile the current official Week 10 status with the committed result-feed state and inspect the Week 10 Game Book capture. The report changes no NFL rows, raw data, model outputs, or capture workflow. The official NFL sources below were fetched with the page-fetch tool on 2026-11-19 UTC; the repository artifacts were inspected locally.

## Executive summary

1. The official NFL Week 10 schedule now marks Chargers–Ravens **FINAL**; the official game-centre page also says **Final** and links the Game Book. The result-feed row is still the immutable 2026-11-17 in-progress capture. The feed is therefore stale for that fixture; its capture-time score must not be treated as the final result. The exact final score is left out of this public audit pending the project's unresolved content-use/redistribution gate. The official schedule link is provided for review.
2. The repository now contains a Week 10 Game Book capture for all 14 scheduled games. Local row-count verification gives **616 starter rows**, **1,308 playtime rows**, and **205 Not Active / Did Not Play rows**, across **28 participating clubs**. `fl2-depth/engine/validate_depth.py` passes 23 structural checks. These are parser/repository counts, not NFL-published totals; one week does not establish a season-long depth order or a pre-game expected lineup.
3. Several 2026-11-17 summaries still say there are no 2026 snaps or that the MNF result is still live. They are historical snapshots and should be superseded by a dated update, not silently treated as current. The old integration audit has been given a warning and link to this page; edits to the active Decision Desk and landing-page scopes are requested, not made here.
4. NFL Terms §1.3 states that systematic retrieval to compile a collection/database is prohibited absent express prior written consent. The capture workflows on current `main` now have a fail-closed authorization guard, but the repository's authorization-variable state could not be queried from this environment (GitHub API returned 403). The public/private data boundary also remains unresolved: GitHub Pages uploads the repository root, which includes row-level NFL-derived files. Do not resume scheduled collection or publish more raw rows until written authorization or a licensed source and a storage policy are established. This is an operational finding, not legal advice.
5. No live/reward strategy is promoted by the existing registries. This report does not change a strategy, correlation, price, or leaderboard number.

## Recommended path before trusting a team or strategy

1. **Resolve data rights and the public/private boundary first.** Obtain written permission or use a licensed provider; document raw retention and derived-publication rights. Keep capture jobs fail-closed until verified.
2. **Use one immutable, permitted input manifest.** Record source, retrieval time, hash, included game IDs, parser version, and all known conflicts. Keep old captures immutable; corrections are new rows/captures.
3. **Build availability as a time series, not a weekly label.** Join dated injury/practice reports and official roster/transaction events to pre-game expected starters, official game-day inactives, actual Game Book starters, and playing time. Preserve shared/empty depth slots and blank values.
4. **Do not convert one week's snap counts into 1st–4th string.** Learn any role/depth feature only from chronological playing-time windows, with explicit position/unit groups and point-in-time cutoffs; validate across all 32 clubs and multiple seasons before any team-level claim.
5. **Test injury/personnel value with paired ablations.** Compare the same model with/without verified availability features on chronological holdouts; report the difference, game-cluster uncertainty and sample size. Do not apply a fixed penalty or interpret an injury level as a surprise.
6. **Keep the competition singles-only until evidence qualifies.** Freeze each strategy before evaluation, publish probabilities with inputs, score against benchmarks with uncertainty/multiplicity control, and require prospective CLV/ROI escrow. Parlays and prop combos require directly measured joint probabilities plus operator-specific push/void rules.
7. **Keep the reviewer queue explicit.** Every open item needs its current answer, missing source, named gate, clearing number, and a direct official link where the item is an NFL fact. Owner-only decisions (price-source budget, data-use permission, reward definition) remain open rather than guessed.
